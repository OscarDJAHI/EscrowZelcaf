## 2. Ce qui a bien marché

- **La colonne vertébrale a tenu.** Les AD se sont mappés proprement sur le code sans forçage : `TransactionAccess` = AD-3, `EvidenceContentValidator` = AD-7, port `EvidenceStorage` = AD-6, fenêtre d'état = AD-2, audit MANDATORY = AD-5.
- **La revue adversariale *avant* le code a payé.** Aucun des 7 trous rebouchés en amont n'est réapparu à l'implémentation.
- **La couche de revue de la boucle attrape du réel** : tie-break de tri (1.3), verrou pessimiste anti-TOCTOU (1.2), plafonnement du nom de fichier — pas du cosmétique.
- **Discipline du ledger `deferred-work`** : les sessions de dev ont elles-mêmes remonté le trou d'intégrité de l'ERD, tranché avant qu'Epic 2/3 n'écrivent des lignes.
- **Conventions brownfield respectées** : entités, migrations Flyway, DTOs, enveloppe d'erreur — le code preuve ressemble au code existant.

## 3. Ce qui a été plus difficile (écarts au plan, tous tracés & vérifiés)

- **Tag MinIO inexistant** : la spine épinglait `RELEASE.2025-10-15T17-29-55Z`, absent de Docker Hub (recherche web initiale erronée) → corrigé en `RELEASE.2025-09-07T16-13-09Z` + spine amendée (`e69d1a0`).
- **Signature du port** : `EvidenceStorage` prend `transactionId` (la signature « figée » ne pouvait pas produire la clé `{txId}/{uuid}` sans lui).
- **Namespace de config** : `escrow.storage.*` (cohérent avec l'existant `escrow.*`), pas `app.evidence.*`.
- **Overrides de version pom** : Testcontainers 1.21.4 (le 1.19.8 du parent parle une API Docker rejetée par Engine 29+), httpclient5 5.6.2 (AWS SDK 2.47.6 exige `TlsSocketStrategy`).
- **Opérationnel boucle** : prompt d'acceptation `bypassPermissions` une fois (débloqué manuellement) ; boucle **tuée 2×** (limites/coût) → bascule vers runs **story-par-story** + worktree propre entre chaque.

## 4. Découverte significative (impacte l'Epic 2)

**Le stockage objet n'est pas transactionnel** : un rollback laisse des objets MinIO orphelins. POC-acceptable en 1.2, mais **l'Epic 2 story 2.1 (ouverture de litige composite et atomique, AD-1)** rend l'orphelinage concret — un échec en cours d'unité atomique doit ne pas laisser de binaire sans ligne.
**Décision (Oscard) :** traiter **avant/dans la Story 2.1** → ajouter `delete(storageKey)` au port `EvidenceStorage` (amendement d'AD-6) + nettoyage best-effort `TransactionSynchronization.afterCompletion` sur rollback.

## 5. Reports ouverts (ledger `deferred-work.md`)

1. **Stockage non-transactionnel** (orphelins au rollback) — *promu action item critique avant 2.1* (voir §4).
2. **`files[]` non borné + bufferisation mémoire** — durcissement DoS, différé.
3. **Liste `GET /evidence` non paginée** — durcissement contrat d'API, à traiter de concert avec la lecture d'audit (même limitation).

## 8. Bilan

Epic 1 a livré un socle preuves complet et testé, fidèle à une architecture qui a remarquablement tenu. Le principal enseignement de process : **le ledger de reports différés + la revue par story fonctionnent** — ils ont attrapé un vrai trou d'ERD et une vraie découverte d'archi avant qu'ils ne coûtent cher.
